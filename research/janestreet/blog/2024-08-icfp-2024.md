# ICFP 2024

- Source: <https://blog.janestreet.com/icfp-2024-index/>
- Published: 2024-08-29
- Kind: blog post

## Summary

- Lists the papers and talks with Jane Street involvement at ICFP 2024 in Milan: modal memory
  management, a non-allocating option, labeled tuples, mixed blocks, interrupts for ML,
  pattern matching on mutable values, the value restriction, and a Flambda2 validator.
- The firm plans to upstream its compiler extensions the way Multicore OCaml was upstreamed,
  and publishes a "bleeding-edge" opam repository with its compiler and the unerased
  versions of its libraries so outsiders can try modes and layouts in practice.
- Bonsai's new API hands a local-mode witness to graph-building code, so escape analysis
  enforces the two-phase (build graph, then run) discipline that the old API left easy to
  break.
- Unboxed types come with a kind system (`value`, `immediate`, `float64`, `bits64`, unboxed
  tuples); mixed blocks let one record hold both GC-scanned pointers and flat unboxed
  fields, as in a trade record with a symbol string next to an unboxed price and size.
- Lacking kind and mode polymorphism, `ppx_template` stamps out one copy of a definition per
  listed kind and mode, as a stopgap closer to the eventual syntax.
- Also noted: labeled tuples (an intern project) spread quickly internally, and `or_null`, a
  zero-overhead option using a null pointer, uses kinds to forbid nesting.

## Relevance to us

- Our prices and sizes are `Fixed_decimal.Make ()` types backed by `int`, but the signature in
  [fixed-decimal](../../../repos/fixed-decimal.md) exports `type t` abstractly without an
  immediacy annotation, so the compiler must treat every `Price.t` field as a possible
  pointer (write barrier on mutation, no specialization).
- Mixed blocks and `or_null` are the features that would matter for
  [market-data](../../../repos/market-data.md) records and
  [order-book](../../../repos/order-book.md) levels if allocation becomes a problem.
- **Action:** mark `type t` as `[@@immediate]` in the `Fixed_decimal.Make` output signature
  and add a test that stores a `Price.t` in an `Obj.repr` check (`Obj.is_int`) to pin the
  representation.
