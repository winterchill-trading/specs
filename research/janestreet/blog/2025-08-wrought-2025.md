# What the interns have wrought, 2025 edition

- Source: <https://blog.janestreet.com/wrought-2025/>
- Published: 2025-08-27
- Kind: blog post

## Summary

- Annual round-up of intern work; a list of short mentions comes first: build priorities in
  the shared action-execution service, a CSS LSP with a validator, generic optional
  arguments, predicate pushdown in the internal data warehouse, and a JIT for the Hardcaml
  simulator.
- One short mention is directly on our turf: a quickcheck-style tool that tests trading
  systems with randomized sequences of market events and shrinks failures to minimal cases.
- JSQL, the firm's own SQL dialect, gained an index-aware in-memory evaluator: it derives an
  over-approximate key range ("selection") from the WHERE clause and executes it against
  `Map.t` (range queries) or `Hashtbl.t` (point lookups) backing stores.
- On 3.8 million rows the indexed evaluator was about 700x faster for an equality filter and
  about 30x faster for a range filter; much of the effort went into API design.
- New ocamltorch bindings use OxCaml's local mode and a `with_rc_scope` function so tensors
  are refcounted and freed deterministically at scope exit, replacing forced
  `Gc.full_major` calls; removing those calls exposed further CPU/GPU sync waste.
- A shared-memory library passes pointers to refcounted objects between trading processes
  instead of re-serializing nested data with shared substructure.
- It uses modes for safety: atomic compare-and-set on counts, `read_write` visibility only
  during initialization and `read` for readers, unique handles so copies must go through an
  explicit increment, and local mode on release, which amounts to borrow checking.

## Relevance to us

- The randomized market-event sequence tester matches a gap in
  [mm-core](../../../repos/mm-core.md): its quickcheck tests cover the pure strategy, while
  the live loop is tested with hand-written scenarios.
- The mode-based refcounting is a good worked example of OxCaml modes (unique, local,
  visibility) for [oxcaml-claude-skills](../../../repos/oxcaml-claude-skills.md); we have no
  cross-process shared memory today.
- **Action:** in `mm-core`, add a Base_quickcheck generator of event sequences (BBO moves,
  trades, fills) driven through `Live.Make` over the in-memory `Venue.S`, asserting that
  absolute position never exceeds the risk limit, and let shrinking minimize failures.
