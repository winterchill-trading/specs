# What the interns have wrought, special jumbo 2026 edition

- Source: <https://blog.janestreet.com/wrought-2026/>
- Published: 2026-09-30
- Kind: blog post

## Summary

- Index post for 2026 intern projects, this year covering ML research and engineering,
  software, Linux engineering, IT, Strategy and Product, and trading desk operations, out
  of hundreds of projects; trading interns are not covered.
- ML engineering: an activation checkpointing planner that reads the `torch.compile` graph
  and greedily picks nodes with the cheapest recompute cost per byte of peak memory freed,
  beating PyTorch's built-in options.
- ML research projects scale to serious training runs within the first week. Two get
  write-ups: an event-level autoregressive diffusion model of market data, and methods to
  measure and remove memorization in LLMs used for prediction.
- Shorter ML items: a network answering per-order questions about the future of any order
  on the book (a variable-size book conditioned on one shared input sequence); a sequence
  model predicting returns and future features with tree-search rollouts and
  self-distillation; KV-cache distillation to speed prefill; bf16 versus fp32 hidden-state
  degradation in a Mamba model.
- Software: Aria tip-recovery indexing (30% less CPU), and `lib/spmd`, an implicit
  single-program-multiple-data DSL in OxCaml for CPU SIMD, inspired by ISPC, Halide and Dex
  (schedule separated from code, reasoning over index sets); its SIMD backend is unfinished
  but early numbers against hand-written intrinsics look promising.
- Also: hash-consing compression of debug graphs in an internal data-fetching library
  (with races between concurrent compressors), ILP/SAT solvers instead of a greedy
  scheduler for placing market data applications on hosts, a coordination protocol for a
  shared optimization-solver cluster, and a feature-engineering library split so helper
  processes compute features and expose them via double-buffered shared memory.
- Linux and IT: a kernel log reporter surviving disk and network failure, an OCaml FUSE
  server for the Depot object store (1.3 GiB/s), and a centralized Windows config
  orchestrator in OCaml with an F# agent, cut over by diffing old and new decisions.
- Pointers to separate posts for trading desk operations and Strategy and Product interns.

## Relevance to us

- **Performance:** moving feature computation into a helper process that publishes
  through double-buffered shared memory keeps the trading loop light. Context only for now:
  [mm-core](../../../repos/mm-core.md) `Market_state` is cheap enough to compute inline.
- **Build and deploy:** placing data applications on hosts is a bin-packing problem where
  solvers beat greedy rules. Context only until the planned AWS deployment
  ([roadmap](../../../roadmap.md)) has more than a few recorders.
- The substantive items have their own notes (Aria indexing, config orchestrator, FUSE
  server, kernel reporter, diffusion, memorization, checkpointing); this index adds no
  further actionable insight.
- **Action:** none.
